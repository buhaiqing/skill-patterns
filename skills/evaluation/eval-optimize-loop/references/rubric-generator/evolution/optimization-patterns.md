# 常见优化模式

## 问题模式与解决方案

### 模式 1: 评测项过严

**症状**: 某项失败率 > 50%

**解决**:
```diff
- Pass 条件: 100% 覆盖
+ Pass 条件: ≥ 80% 覆盖
```

### 模式 2: 评测项模糊

**症状**: 用户反馈「不知道怎么满足」

**解决**:
```diff
- Pass 条件: 代码质量好
+ Pass 条件: ESLint 0 errors，圈复杂度 < 10
```

### 模式 3: 缺少行业细节

**症状**: 某项从未失败（可能太松）

**解决**:
```diff
- Pass 条件: 性能可接受
+ Pass 条件: P99 < 100ms，QPS ≥ 1000
```

### 模式 4: BLOCKER 过多

**症状**: 平均轮次 > 3

**解决**:
- 将部分 BLOCKER 降级为 normal
- 拆分复杂项

### 模式 5: 重复项

**症状**: 两项总是同时通过/失败

**解决**:
- 合并两项
- 删除较弱的一项

## 行业特定优化

### 金融

| 问题 | 优化 |
|------|------|
| 精度要求 | 明确 Decimal 位数 |
| 对账时效 | 区分 T+0/T+1 |
| 合规检查 | 引用具体法规条款 |

### 量化

| 问题 | 优化 |
|------|------|
| 回测标准 | 明确夏普比率阈值 |
| 过拟合 | 增加样本外测试要求 |
| 成本模型 | 明确滑点计算方式 |

### Python

| 问题 | 优化 |
|------|------|
| 类型检查 | 允许渐进类型 |
| 异步 | 提供同步替代方案 |
| 测试 | 区分单元/集成测试 |

### Go

| 问题 | 优化 |
|------|------|
| 错误处理 | 提供错误包装示例 |
| Context | 明确超时设置 |
| 性能 | 提供基准测试模板 |

## 优化决策树

```
某项失败率高？
  ├─ 是 → 是否过严？
  │       ├─ 是 → 放宽要求
  │       └─ 否 → 用户能力不足？
  │               ├─ 是 → 补充文档
  │               └─ 否 → 保持
  └─ 否 → 某项从未失败？
          ├─ 是 → 是否过松？
          │       ├─ 是 → 收紧要求
          │       └─ 否 → 保持
          └─ 否 → 平衡良好，保持
```

## 版本升级策略

### 小幅优化 (v1.x → v1.y)

- 单个项调整
- 不影响整体流程
- 向后兼容

### 重大更新 (v1 → v2)

- 结构调整
- 新增/删除项
- 不兼容变更
- 需用户确认

## A/B 测试模板

### 方法

1. 创建 v1.1 测试版本
2. 50% 用户使用 v1.1
3. 对比关键指标
4. 决策是否升级

### 指标

- 平均轮次
- 成功率
- 用户评分
- 完成时间
