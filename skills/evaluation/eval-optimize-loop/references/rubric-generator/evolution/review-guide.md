# Rubric 复盘指南

## 何时复盘

### 自动建议（满足任一）

| 条件 | 阈值 |
|------|------|
| 使用次数 | ≥ 5 次 |
| 距离上次复盘 | ≥ 30 天 |
| 平均评分 | < 3.5 |
| 连续失败 | ≥ 3 次 |

### 手动触发

```
「复盘」                          → 展示列表
「复盘 {rubric-id}」              → 特定模板
「推荐复盘」                      → AI 推荐
```

## 复盘分析维度

### 1. 使用统计

```yaml
metrics:
  - 使用次数
  - 平均轮次
  - 成功率
  - 平均评分
  - 平均耗时
```

### 2. 问题分析

```yaml
issues:
  - 高频失败项（Top 3）
  - 用户反馈关键词
  - 平均失败轮次
  - 阻塞点分析
```

### 3. 优化方向

```yaml
improvements:
  - 过于严格的项（失败率 > 40%）
  - 模糊的项（无明确证据）
  - 缺失的项（用户建议）
  - 重复的项（可合并）
```

## 复盘报告解读

### 示例报告

```markdown
## python-service 复盘报告

### 📊 统计
- 使用次数: 8
- 平均轮次: 2.5 (目标 ≤ 3)
- 成功率: 87%
- 平均评分: 4.3/5

### 🔍 问题
| 项 | 失败率 | 说明 |
|----|-------|------|
| PY1 | 50% | 类型提示要求过严 |
| PY4 | 37% | 异步检查不明确 |

### 💡 建议
1. PY1: 放宽类型检查要求
2. PY4: 补充异步检查示例

### 📋 决策
[应用] [编辑] [忽略]
```

## 决策指南

### 应用建议

- ✅ 失败率 > 40% 的项
- ✅ 用户明确反馈的项
- ✅ 行业实践更新的项

### 编辑建议

- ⚠️ 部分合理的建议
- ⚠️ 需要权衡的项

### 忽略建议

- ❌ 不符合当前业务
- ❌ 暂时不需要优化
